## 2. 事件、调度与交谈

### 2.1 从执行到下一步

1. 日程或临时活动进入角色当前事件。后端下发目的地，Godot 寻路并上报楼层、区域和坐标。需要到场的活动从确认到达后累计停留。
2. 活动检查点或 NPC 交谈结束时，按事件类型发起异步判断。模型参考活动事实、实时位置、附近角色和公告栏、关系、活跃记忆及反思洞察。
3. 模型可以请求找人交谈、去活动目录允许的地点做事、延长当前活动，或继续原安排。后端校验目标、活动类型和是否允许延长。可执行的后续动作生成自己的事件并关联来源。
4. 事件事实、各角色的判断与后续决定一起进入时间线。同一场对话可以有两份不同的角色判断。读公告属于阅读事件，完成后形成记忆，供后续常规决策检索。

### 2.2 优先级和待办

| 档位 | 行为 | 抢占规则 |
| --- | --- | --- |
| 低 | 基础作息及常规计划 | 自主响应和玩家指派可以暂挂低档活动。 |
| 中 | 事件后续、主动交谈、被寻找、读公告等 | 普通同档活动开始后继续。排队活动先按到期时间，再按入队顺序选择。 |
| 高 | 悄悄话及手动指派 | 可以接管普通中低档活动。退场是世界状态变更，优先处理并暂停角色。 |

中档内，「被寻找」和「读公告」都可暂挂普通中档活动。「被寻找」可以暂挂阅读，正在进行的交谈继续。恢复时尽量接续原进度。好感、活跃记忆和洞察影响角色选择；调度使用档位和上述同档规则。

### 2.3 找人和播放

- 发起者沿途更新目标的位置和区域。双方同层并进入 96 地图像素范围时，给对方登记「被寻找」待办，到可接手时停步等待。两人互相寻找时合并为同一次邀约，并随机指定一方等待。
- 交谈需确认同层、同区域、32 地图像素以内并站定。落点选在对方身旁可走的位置。到场后，接受方结合当前活动和后续时间窗口，选择现在聊、简短聊、稍后聊或婉拒。
- 邀请、回复和实际对话按顺序进入气泡队列和日志。完成播放后结束对话并释放占用。世界暂停会冻结 NPC 对话和气泡进度。自主行动提示使用独立的短句气泡，带「（自言自语）」前缀。

## 3. 公告、旁听与角色记忆

- **公告**。NPC 在公告栏所在的同层走廊区域内，距离 384 地图像素以内可发现未读公告。走到板前 48 地图像素内并站定后开始读。寻路、阅读和完成属于同一个事件。发布只提交正文，删除后已读角色的记忆与历史仍可查看。
- **旁听**。判断使用最近 2 现实秒内上报的实际位置。同一楼层、同一区域内，距说话者不超过 150 地图像素的第三方 NPC 可以记住听到的台词。中途加入或离开只会取得经过时听到的片段。NPC 之间和玩家参与的交谈都支持旁听，结案后异步写入各角色的「旁听交谈」记录。
- **回忆**。生成提示提供角色性格、对在场人物的好感、活跃记忆和洞察。模型评定重要性和情绪，可以略过、记错或补全细节。公告正文、实际台词和占用时间仍取自原始事件。模型不可用时，普通回忆根据实际经历保存，反思留待下一次维护。
- **存档**。SQLite 保存全局事件、角色知情范围、模型判断与活动关联。时间线按角色知情范围展示。公告、台词和记忆各自保留来源，检查点恢复用稳定事件和记忆 ID 去重。旧公告阅读记录可回填，早期版本尚未处理的公告判断会在启动时收尾。

### 调试入口

| 接口 | 查看或操作 |
| --- | --- |
| `GET /world` | 当前世界、角色位置和目标、当前事件，以及 `world_id`。 |

## 4. Godot 操作与上帝模式

- **地图**。按住左键拖动镜头，滚轮缩放，数字键 1／2／3 切换观察楼层。玩家加入后用方向键或 WASD 行走，近处按 E 交互，踩箭头换层，按 P 回到玩家。拖动超过阈值后取消本次点击，面板滚动和地图缩放分别处理。
- **观察**。角色状态栏显示实际楼层和房间，楼梯间也显示为走廊。左侧卡片、折叠按钮和事件卡具有悬停白边。临时跟随移出后恢复视角。社交观察统一使用顶部角色选择器，角色资料展示基础日程的时间、地点和行为。其他页提供事件时间线、记忆、关系和对话日志。面板可拖动，再按入口或点 X 关闭。
- **时间**。右上角集中显示时钟、暂停、倍率、定时快进、后端连接、对话事件流和模型配置。模型配置状态表示密钥已填写，连通性需要通过实际请求检查。机制说明位于右下角。
- **上帝模式**。公告与悄悄话各有独立子页，历史在上，输入在下。悄悄话可指派去某处、做目录内的活动、原地停留或找人，接收指令的角色会尝试执行，作为目标的另一位角色仍经过邀约判断。悄悄话解析需要可用模型。
- **退场和重置**。通过角色状态栏选择退场或出演。退场角色暂停活动与记忆维护、解除相关占用，并从寻找候选移除。灰色卡片仍可查看资料，出演后继续可恢复的活动。重置需确认，会清除当前运行数据，恢复默认日程、初始关系和初始位置，从第一天 08:00 开始。

## 5. 启动和验收

### 5.1 本地启动

在仓库根目录准备 Python 3.11 的 `.venv` 并安装 `requirements.txt`，安装 Godot 4.5.2 stable 标准版。Windows 可双击 [启动脚本](../Start-Roamchestra.bat)。脚本先启动单进程后端并检查 `127.0.0.1:8000/health`，再启动 Godot，退出游戏时停止本次启动的后端。Godot 安装在其他位置时，可将 `GODOT_EXE` 设置为可执行文件的完整路径。

手动联调时，先运行 `python -m uvicorn backend.api:app --host 127.0.0.1 --port 8000`，再打开 Godot 的 `frontend/project.godot`。右上角「后端驱动」表示前后端已连通。真实模型参数通过本地 `.env` 配置，模板见 [.env.example](../.env.example)。

双击脚本使用正式交互入口和当前本地存档。命令行演示用 `fresh_db=True` 初始化数据库。需要保留现有世界时，先停机备份 `data/memory.db`，并使用临时存档做重置或演示验证。密钥、玩家凭据、运行数据库和缓存不进入交付。

### 5.2 自动检查

从仓库根目录执行。运行 Godot 相关检查前，将 `GODOT_EXE` 指向已安装的 Godot 程序，Windows 上可选带控制台的版本。

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m unittest discover -s tests -q
$godotTestLog = Join-Path ([System.IO.Path]::GetTempPath()) 'roamchestra-social-ui.log'
& $env:GODOT_EXE --headless --path frontend --script (Resolve-Path '.\tests\check_social_ui.gd').Path --log-file $godotTestLog
.\.venv\Scripts\python.exe -X utf8 -B tests/run_noticeboard_smoke.py
```

本次交接前通过 **148 项后端测试**、Godot 社交界面专项和临时后端公告联调。后端使用模拟模型，覆盖 150 像素边界、隔房隔层、过期位置、部分旁听、事件来源和回忆差异。Godot 检查覆盖时间线、气泡、公告、悄悄话、退场／出演及确认重置。

### 5.3 接手后的可见窗口验收

1. 加入玩家，走过楼梯箭头，确认换层、按 E 交互、拖动镜头和悬停角色卡的行为。
2. 下达「找某人交谈」的悄悄话，观察追踪、被找者停步等待、就近站定、邀约回应、暂停／继续和交谈后恢复活动。双方时间线应共享实际台词，各自显示判断。
3. 发布一条公告，观察 NPC 走到板前再读，检查公告原文和读者记忆。撤下公告后复查以前的记录。观察靠近交谈者的第三方 NPC 是否生成旁听印象。
4. 让角色退场，再出演，确认名单、地图和活动状态一致。用测试存档验证重置后时钟、位置和默认日程。

## 6. 已知边界与待接手事项

1. **真实模型试玩**。优先用正常倍率跑一段完整交互，记录活动是否完成、邀约是否太少、模型排队时等待多久，以及记忆能否保留到下一次交谈。对话与向量请求共用可配置并发上限，默认 3。旧向量维度不兼容时会改用关键词相关度。
2. **赴约时间估算**。现有走路确认、等待超时和活动到期仍分别处理，尚未用路线长度、移动速度和双方空闲窗口估算最早到达时刻。「稍后聊」会结束本次邀约，具体的双方约定时间有待建模。
3. **正式八卦候选**。现有转述会对活跃来源去重并限制最多三跳。事件结果找人和悄悄话找人走 `Scheduler.event_talk()`，目前传入空候选。若要让这些路径也正式转述，可从该入口接入已有的候选和分享判断。
4. **时间和记忆节奏**。默认原速仍是现实 1 秒对应游戏 10 分钟，记忆新近度半衰期为 300 游戏分钟。放慢世界时钟和延长记忆保留分别影响日程、行动和社交，当前倍率和遗忘参数沿用现有设定。
5. **活动结果的边界**。后端确认角色实际到达和停留，活动结果由角色模型解释。科研、查阅等活动目前使用活动目录和停留机制，尚无实验设备或独立的任务执行判定。
