# 任务01：公开人格卡与角色详情面板

更新日期：2026-11-14。基于包含 `fd87015` 的版本开发，本任务只新增公开资料查询和 Godot 人物详情，不改模型、记忆、调度、时间倍率或地图规则。

## 如何使用

运行后端与 Godot 主场景，打开“社交观察 / 收起”，默认进入新增的“角色资料”页。通过现有角色下拉框切换人物，右上角“刷新资料”重新读取公开资料，无需配置模型密钥。

资料页展示已有像素头像、姓名、身份、性格标签、专长、短长期目标、说话风格、口头禅、当前位置、当前目标和按时间排序的日程。目标与日程使用原有人格卡和世界区域数据，不从前端旧名册的角色描述推测身份。

为让人物信息更清楚，资料页暂时收起会面、模型状态及记忆时间线控件；切回原有记忆、关系或日志页后恢复原布局。世界暂停和倍速控制仍可用。长文本、长标签及日程在页内换行、滚动，不扩张整个观察面板。

## 公开范围与秘密边界

公开人格字段采用明确的白名单：

- `name`、`role`、`title`：姓名、身份类别与公开头衔。
- `expertise`、`mbti`、`traits`：专长及性格展示。
- `tone`、`catchphrase`：公开说话风格与口头禅。
- `goals.short_term`、`goals.long_term`：本任务规定为公开的目标。
- `schedule`：人格卡日程，服务层附上地图和地点名称。
- `location`、`destination`、`game_time`：世界快照中的实际地点、当前目标和游戏时间。

`secrets`、`initial_relations`、`example_lines`、原始提示词及将来增加的内部字段不进入此响应。没有序列化整个 dataclass 再删除敏感字段，也没有将原始人格卡复制到前端资源。

`PersonaCard.public_profile()` 只建立公开字段副本；`GameService.public_npc_profile()` 补充地点和日程。API 另用明确的嵌套响应模型限定输出，防止内部新增字段被意外发送。Godot 逐项读取展示字段，文本使用普通 Label，不能执行卡片内容中的富文本标记。

原有 `render_secret_hint()` 与模型提示词流程保持不变，秘密仍只按现有规则进入本人上下文。本任务没有改变旧的调试/记忆观察接口，也没有禁止原剧情允许的模型转述或秘密披露；新增公开资料接口不会直接提供秘密字段。

## API

`GET /npcs/{name}/profile`，`name` 使用与现有 NPC 接口一致的中文姓名，例如：

```text
GET /npcs/陈卷/profile
```

返回 `name`、`role`、`title`、`expertise`、`mbti`、`traits`、`tone`、`catchphrase`、`goals`、`schedule`、`location`、`destination`、`game_time`。

`schedule` 为 `[{"time":"08:30","location":{...}}]`；地点对象包含 `area`、`name`、`map_id`、`room_id`。旧日程地点别名按现有世界清单转换，同编号房间仍区分楼层。未知日程地点显示“未知地点”，未知角色返回404。

此查询不调用模型、不写记忆、不修改角色目标。运行中的世界时钟仍按原有世界快照机制同步，不因查询额外快进。

## 离线与异常

- 后端未连接且无缓存时，仍展示本地人物姓名、头像和可获得的实际位置，提示启动后端读取完整资料，不伪造人格目标或日程。
- 已同步过的公开静态资料可在本次游戏进程中缓存使用；断线时明确标为“上次同步”，位置改为本地演示位置。
- 当前地点与目标优先跟随已有世界快照更新，不需要为了刷新位置持续重取人格卡。
- 角色切换后，旧请求只写入所属角色的缓存，不覆盖新选择；超时、404和失败有提示，并可手动重试。
- 缺少可选字段时使用“未填写 / 未设置日程”，不影响其他资料显示。
