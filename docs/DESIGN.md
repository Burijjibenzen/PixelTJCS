# 校园多智能体交互系统 · 需求与设计方案

> 课程大作业：基于校园场景（纪事楼 3/4 楼、智信馆 4 楼）的 NPC 自主交互演示系统
> 基座项目：`hello-agents-main/code/chapter15/Helloagents-AI-Town`（Godot 4 前端 + FastAPI 后端）
> 文档版本：v0.3（2026-11-08：M2.2 前端↔后端联动完成，更新 §7 第 3 条为已完成）

> 2026-11-15 实现状态补充：本文保留原需求与早期里程碑；实际地图已为济事楼三/四楼及智信馆二楼。M4现拆为[M4.1已实现成果](M4.1.md)和 M4.2，当前行为、验证和待办以阶段交接及[CODE_GUIDE.md](CODE_GUIDE.md)为准。

## 1. 项目目标

在"赛博小镇"基础上重构为**以 NPC 之间自主交互为核心**的校园多智能体系统：

- **场景**：纪事楼 3F / 4F、智信馆 4F（像素风复刻楼层结构，复制模板 + 填充场景元素）
- **角色**：导师 + 若干研究生，每个角色一张**人格卡**
- **核心演示点**：NPC↔NPC 自主对话、记忆的形成与**遗忘（可视化）**、人格差异、关系演化
- **加分项**：玩家模式开关——开启后玩家实体进入场景与 NPC 互动并产生影响；默认关闭（纯 NPC 交互）

## 2. 现状盘点（基座项目能给我们什么）

| 能力 | 现状 | 处置 |
|---|---|---|
| Godot 前端 | 单一办公室地图；NPC 随机巡逻；玩家 E 键交互；气泡轮询显示 | 移动/气泡思路复用；**地图已重做**：纪事楼 3F 真实布局自动提取 13 区域（M2.1 完成，技术细节见 CODE_GUIDE §6） |
| FastAPI 后端 | `/chat` 玩家↔NPC 对话；`/npcs/status` 每 30s 批量生成状态 | API 骨架复用 |
| 记忆系统 | hello-agents `MemoryManager`：工作记忆(10条/2h)+情景记忆(100条, SQLite+Qdrant)，衰减系数 0.95、重要性阈值 0.3 | **思路借鉴、实现自研**（框架内部是黑盒，无法演示遗忘过程） |
| 好感度系统 | LLM 情感分析 → 0-100 分 → 影响语气；只建模 NPC→玩家 | 扩展为 **NPC↔NPC 关系矩阵** |
| LLM 接入 | ModelScope Qwen2.5-72B（OpenAI 兼容接口） | 直接沿用 |

**关键缺口（= 本次大作业的主要工作）**：

1. **NPC 之间没有任何真实交互**。现有"自主对话"是每 30s 一次批量生成的独白气泡（`batch_generator.py`），无感知对象、无多轮对话、无记忆沉淀。
2. 记忆只记录玩家对话；NPC 的日常见闻（看见谁、听到什么）不产生记忆；遗忘机制藏在框架内部，**不可展示**。
3. 角色是 3 个扁平配置（无目标、无日程、无隐私），距"校园 + 导师 + 学生"设定差距大。
4. 玩家交互常开，缺少"纯观察模式"与开关。

## 3. 需求梳理

**功能需求**

- **FR-1 场景**：3 张楼层地图（纪事楼 3F/4F、智信馆 4F），同一套瓦片模板复制楼层结构；楼梯互联。
- **FR-2 功能分区**：
  - 实验室——日常科研活动与工作事件的主要发生地（工位、设备、白板）；
  - 导师办公室——导师专属空间，学生可被**召见**（事件驱动交互）；
  - 公共场所（厕所/茶水间）——**共享情境**，制造偶遇、提升互动频率。
- **FR-3 NPC 自主性**：日程驱动移动；同区域相遇可触发对话；对话内容受人格、记忆、关系共同影响。
- **FR-4 记忆系统**：每个 NPC 独立记忆；记录对话、观察（看见/听见）、事件（被批评、论文中稿）、反思结论。
- **FR-5 遗忘可视化**：面板展示每条记忆的实时强度；已遗忘记忆进入"遗忘档案"；支持回放"某 NPC 在时刻 T 记得什么"。
- **FR-6 关系系统**：NPC↔NPC 好感度矩阵（新增）+ NPC↔玩家（沿用）；关系影响搭话意愿与语气。
- **FR-7 人格卡**：JSON 卡片驱动全部行为差异，前端可查看卡片。
- **FR-8 玩家开关**：默认关闭；开启后玩家加入感知与关系体系；关闭后退出、NPC 保留关于玩家的记忆。
- **FR-9 观测调试**：对话日志、记忆面板、关系图谱、时间加速、强制偶遇（演示用）。

**非功能需求**：演示可控可回放；API 成本可控（国产模型 + 事件驱动调用）；单机可跑（不部署向量库服务器）。

## 4. 系统架构

```
┌─────────────────── Godot 4 前端 ───────────────────┐
│ 三张楼层地图 │ NPC日程移动 │ 对话气泡(轮次播报)      │
│ 玩家开关 │ 记忆面板(遗忘可视化) │ 关系面板 │ 时间加速 │
└──────────────────────┬─────────────────────────────┘
            WebSocket(事件流) + HTTP(查询/操作)
┌──────────────────────┴────────────── FastAPI 后端 ──┐
│ WorldEngine   游戏时钟 / 区域占用 / 事件总线         │
│ Scheduler     相遇检测 → 触发对话 / 日程调度         │
│ AgentRuntime  每个NPC一个LangGraph子图:             │
│               感知→决策→行动→对话→写记忆→(周期)反思  │
│ MemoryService 自研记忆服务: 存储/检索/遗忘/反思/导出 │
│ RelationGraph NPC↔NPC / NPC↔玩家 关系矩阵           │
│ PlayerMode    玩家开关 / 感知注入 / human-in-the-loop│
└──────────────────────┬─────────────────────────────┘
        LangChain 组件: ChatOpenAI(Qwen) / Embeddings(本地bge-zh)
            存储: SQLite(记忆/关系) + Chroma或sqlite-vec(向量)
```

**后端模块清单（重构 backend/）**：`world.py`（时钟/区域/事件）、`scheduler.py`（相遇+调度）、`persona.py`（人格卡）、`memory.py`（自研记忆，核心）、`conversation.py`（NPC↔NPC 对话引擎）、`relations.py`、`player_mode.py`、`api.py`（保留旧端点兼容）。

## 5. Agent 核心功能设计

### 5.1 人格卡（Persona Card）

每张卡一个 JSON 文件（`personas/严导师.json` 等），启动时加载并渲染进系统提示词：

```json
{
  "name": "陈卷",
  "role": "博士生（博四）",
  "public_info": { "title": "课题组大师兄", "expertise": "强化学习、GPU调度" },
  "personality": { "mbti": "ENTJ", "traits": ["好胜", "爱操心", "嘴硬心软"] },
  "style": { "tone": "语速快，爱用反问句", "口头禅": "这周能跑完吗？", 
             "example_lines": ["这数据不对吧，重跑。"] },
  "goals": { "short_term": "周五前跑完对比实验", "long_term": "发一篇CCF-A毕业" },
  "secrets": ["其实上次组会PPT是抄师兄的框架"],
  "schedule": { "09:00": "实验室工位", "12:00": "外出午饭", "14:00": "实验室",
                "16:00": "导师办公室汇报", "18:00": "实验室" },
  "initial_relations": { "严正": 45, "林摸摸": 70 }
}
```

设计要点：
- **同一事件、不同人格 → 不同反应**（答辩对比点：被导师批评后，"卷王"自省加练、"摸鱼侠"摆烂吐槽）；
- `secrets` 只写入本人记忆，可被关系好的 NPC"套话"出来——制造戏剧性与信息传播链；
- `schedule` 是自主移动的依据，也让"厕所偶遇""办公室召见"成为日程与事件的自然结果。

### 5.2 记忆系统与遗忘（核心卖点）

**记忆类型**：对话记忆 / 观察记忆（看见谁在哪、听见对话）/ 事件记忆（被批评、中稿）/ 反思记忆（结论）。

**单条记忆结构**：`{id, agent, content, type, importance(0-1), emotion, game_time, location, participants, strength}`

**检索打分**（Stanford Generative Agents 公式）：

```
score = α·recency(指数衰减) + β·importance + γ·relevance(向量余弦相似度)
```

**遗忘三机制（全部可视化）**：

| 机制 | 规则 | 演示表现 |
|---|---|---|
| 时间衰减 | recency 按 half-life 衰减，可调时间加速 | 记忆强度条肉眼可见地下降 |
| 容量淘汰 | 超容量时淘汰 score 最低者 | 被淘汰记忆移入"遗忘档案"（灰色划线） |
| 反思压缩 | 每 N 条记忆触发反思：琐碎记忆被压缩为一句结论 | 星标"洞察"取代多条原始记录，原始记录淡出 |

**可视化面板**：选 NPC → 记忆时间线（活跃=彩色、已遗忘=灰色、反思=星标）+ 强度条 + 遗忘档案；支持时间滑块回放"此刻 TA 检索时会想起什么"。
**时间加速**：默认 1 现实秒 = 10 游戏分钟（可调），让遗忘在答辩现场"几分钟内"发生。

### 5.3 感知–决策–行动循环

每个游戏 tick 执行：**感知**（附近的人/听到的八卦/当前时间）→ **决策**（继续日程 / 发起对话 / 移动去某处）→ **行动** → **写记忆** → （周期性）**反思**。

实现原则：**规则打底、LLM 增强**——移动与相遇检测用规则（便宜稳定），"是否搭话/说什么/是否传播八卦"交给 LLM 结构化输出（`with_structured_output` 返回 JSON），保证下限、控制成本。

### 5.4 NPC↔NPC 对话引擎（系统灵魂）

**触发条件**（满足其一且冷却已过）：同区域共处（日程交汇或事件导致，如同去厕所、被一同召见）／事件触发（导师叫学生）／关系热度高主动找上门。

**流程**：发起方生成 `意图 + 开场白` → 双方按（人格卡 + 各自检索到的记忆 + 当前关系）轮流回复 2~4 轮 → 结束语 → **双方各自写记忆**（内容不同视角！各自 importance 由 LLM 评定）→ 关系矩阵更新 → 低重要性"听说"记忆埋下八卦伏笔。

**前端表现**：气泡按轮次顺序在双方头顶交替播报——这是答辩时最有说服力的画面。

### 5.5 关系系统与八卦传播

- 关系矩阵 `relations[A][B] ∈ [0,100]`：影响主动搭话概率、说话语气、是否愿透露 secrets；
- **八卦传播**：A 与 B 对话的结论，以较低 importance 写入 A 对 C 的"听说"记忆 → 形成"办公室消息链"，让交互产生可观察的涟漪。

### 5.6 玩家模式（加分项开关）

- `player_enabled=false`（默认）：纯 NPC 世界，演示多智能体自主性；
- 开启：玩家实体进入感知范围与关系矩阵；玩家走近 NPC 按 E 触发对话（复用现有 `/chat`，升级为带记忆/关系上下文）；玩家说的话影响 NPC 记忆与好感度，间接改变 NPC 之间的行为；
- 技术上用 LangGraph `interrupt()` 做 human-in-the-loop；关闭时把玩家从感知中移除，NPC 保留相关记忆。

## 6. 框架选型

**结论：LangGraph（LangChain 生态的智能体编排层）+ LangChain 组件。**

你们觉得 LangChain 合适的方向是对的——但注意 2024 年后 LangChain 官方已把智能体编排统一指向 LangGraph。LangGraph 底层直接复用 LangChain 的模型接入、提示词模板、结构化输出，属于同一套技术栈、同一份学习成本，但多了你们最需要的"有状态编排"能力。

| 候选 | 定位 | 优势 | 对本项目的短板 |
|---|---|---|---|
| **LangGraph** ⭐ | 有状态智能体编排（图/状态机） | 状态共享、条件边、循环、checkpoint 持久化、`interrupt()` 人机协同、多智能体模式官方支持 | 概念较多，有学习曲线 |
| LangChain 单用 | 组件库（模型/提示词/输出解析） | 生态最大，入门快 | 多智能体轮次编排需全手写循环 |
| AutoGen (MS) | 群聊式多智能体 | GroupChat 圆桌对话开箱即用 | 偏"会议讨论"，世界模拟/日程调度的控制粒度不足 |
| CrewAI | 角色分工任务流 | role/goal 与人格卡天然契合 | 偏任务流水线，开放式世界模拟受限 |
| 无框架自研 | asyncio + OpenAI SDK | 零依赖、控制力最强、适合讲原理 | 无编排抽象，工程量大，学不到工业界框架 |

**选 LangGraph 的四个理由（一一对应你们的功能）**：
1. NPC↔NPC 多轮对话 = 小型状态图（发起 → 轮流回复 → 是否继续 → 总结 → 双方写记忆），条件边+共享状态正是它的核心场景；
2. 玩家开关 = `interrupt()` human-in-the-loop 的一等公民特性；
3. 每个 NPC 一个子图（感知→决策→行动→反思），由世界循环驱动；
4. SQLite checkpointer 持久化图状态 → 可断点续演、答辩现场回放。

**重要原则：记忆服务自研，不用框架内置记忆。** 遗忘的内部过程（衰减公式、淘汰、反思压缩）恰是你们的演示核心，黑盒组件反而无法展示；自研 SQLite + 本地向量的代码量不大（几百行），且本身就是大作业的技术亮点。

**配套选型（国内可用 + 低成本）**：
- 对话模型：沿用 Qwen 系列（`langchain-openai` 的 `ChatOpenAI` + 自定义 `base_url`，ModelScope/DashScope/DeepSeek 均兼容）；闲聊/状态用 `qwen-turbo` 级小模型，关键对话/反思用大模型；
- Embeddings：本地 `sentence-transformers` + `bge-small-zh-v1.5`（免费离线、中文友好），或硅基流动 embedding API；
- 向量存储：Chroma（嵌入式，免部署）或 sqlite-vec，**弃用 Qdrant 服务器**；
- 版本管理：LangGraph 迭代快，`requirements.txt` 锁定版本。

## 9. 答辩演示脚本（约 8 分钟）

1. **场景漫游**（30s）：三楼层 + 三功能区介绍；
2. **人格卡**（30s）：展示两张对比鲜明的人格卡（卷王 vs 摸鱼侠）；
3. **自主交互**（2min）：注入"组会通知"事件 → 实验室里学生们自主讨论；厕所偶遇闲聊；
4. **导师召见**（2min）：学生 A 被叫进办公室 → 出来后情绪与关系变化 → 找同学 B 吐槽 → 八卦传播到 C；
5. **记忆遗忘**（2min）：时间快进 3 天 → 记忆面板看强度衰减、记忆进入遗忘档案 → 让 B 问 A"还记得 X 那天说什么吗" → A 模糊/记错 → 与面板互相印证；
6. **玩家模式**（1min）：打开开关，玩家与 NPC 对话影响好感度与记忆，展示 human-in-the-loop。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 成本/延迟 | 事件驱动调用而非定时轮询；小模型跑量、大模型跑关键；提示词缓存；限制对话轮次 |
| LLM 输出不稳定 | `with_structured_output` + JSON 修复 + 规则兜底（保留预设对话降级，沿用现项目做法） |

| 三张地图工作量 | 同一瓦片集 + 楼层模板复制，仅改房间布局与元素 |
| 演示现场网络/API 抖动 | 时间加速离线回放模式（预录事件流）；`/debug/force_meet` 兜底 |
