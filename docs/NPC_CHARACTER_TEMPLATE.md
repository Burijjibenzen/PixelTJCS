# PixelTJCS 角色设计模板

每个 NPC 复制下方的「角色卡」填写一份。填写现有角色名或文件名作为替换目标，例如 `lulu.json`，方便确认从哪个角色沿用贴图和地图出生点。此 Markdown 用于编辑设定，游戏读取的是 [后端人格卡 JSON](../personas/) 和 [Godot 角色名册](../frontend/data/npc_roster.json)。

对照填写时可以查看 [现有 10 个角色的设定](NPC_CURRENT_CHARACTERS.md)。

## 角色卡

### 角色姓名

- **替换对象** `待填旧角色名或现有 JSON 文件名`
- **新姓名 `name`** `待填，角色之间不能重名，同小济留给玩家角色`
- **身份类别 `role`** `student 学生 / advisor 导师 / staff 教务或行政`
- **性别 `gender`** `男 / 女`
- **公开头衔 `title`** `待填，例如 博士生（博二）· 课题组助教`
- **擅长 `expertise`** `待填，写角色能聊什么、能帮谁解决什么问题`
- **MBTI `mbti`** `待填，可留空`

#### 性格和说话方式

- **性格关键词 `traits`** `待填 3–5 个，可以写平时和遇到压力时的反差`
- **说话风格 `tone`** `待填，写语速、措辞、句式或不同情绪下的变化`
- **口头禅 `catchphrase`** `待填一句`
- **示例台词 `example_lines`**
  1. `填一句平时会说的话`
  2. `填一句遇到压力、求助或冲突时会说的话`

台词既会给模型参考，也会在模型不可用时直接显示。尽量用第一人称写完整短句。

#### 目标和隐藏设定

- **短期目标 `goals.short_term`** `待填，写近期要完成的具体事情`
- **长期目标 `goals.long_term`** `待填，写这个角色长期想追求什么`
- **角色秘密 `secrets`** `待填，可写多条或留空。此字段会进入该角色的对话上下文，仅供角色扮演使用。`

#### 基础日程 `schedule`

| 游戏时间 `HH:MM` | 地点名或区域 ID |
| --- | --- |
| `08:30` | `待填` |
| `12:00` | `待填` |
| `14:00` | `待填` |

填好预期时间和地点即可。导入时会核对地图区域 ID，例如 `zhixinguan_floor2/zx2_lib` 对应智信馆二楼图书馆。这里是基础作息，游戏运行中还会安排动态活动。

#### 初始关系 `initial_relations`

| 对方的新姓名 | 初始好感度 `0–100` | 关系背景（设计备注） |
| --- | --- | --- |
| `待填` | `50` | `可填相识经过、合作或矛盾` |

没填的关系默认是 50。同一对角色共用一个好感度，双方可以写同一分数。关系背景是设计备注。如果希望 NPC 能聊起这段经历，可以把相关内容纳入这两位角色的设定。

#### 外观和地图（可选）

- **外观** `沿用旧角色贴图，或填新素材路径、配色、服装等识别特征`
- **前端出生点** `沿用旧角色出生点，或填楼层和房间`

## 替换时需要对应的数据

| 你填写的内容 | 项目中的对应位置 |
| --- | --- |
| 姓名、身份、性格、台词、目标、秘密、基础日程和初始关系 | `personas/<角色文件名>.json` |
| 地图显示名、贴图、颜色和出生点 | `frontend/data/npc_roster.json` 的 `name`、`char`、`tint`、`home_map`、`home` |

后端人格卡和前端名册的 `name` 需要一致。现有 10 个角色可以按原名册 `id` 一对一替换。运行存档里的 NPC 记忆和关系按姓名关联，填写替换对象可以帮助后续确认旧记录的归属。
